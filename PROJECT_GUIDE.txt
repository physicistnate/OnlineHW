-------------------------------------------------------------------------------
1. WHAT THIS IS
-------------------------------------------------------------------------------

A homework system for IB, AP and general high-school physics and
precalculus/calculus. It does not use any existing online homework system.
Phase 1 is a working website with no database yet. Everything a student does
is saved in their own browser, which is enough to test the whole question
engine before real accounts are added in Phase 3.

Starting course: IB Physics SL. Starting topic: A.1 Kinematics (7 questions).

Technology: a static website (Vite + React + TypeScript), maths rendered with
KaTeX, graphs drawn as SVG. No server is needed, so it can be hosted free on
GitHub Pages. The planned database is Supabase (free tier).


-------------------------------------------------------------------------------
2. RUNNING IT ON YOUR COMPUTER
-------------------------------------------------------------------------------

One-time setup:
  1. Install Node.js 22 (LTS) or newer from https://nodejs.org
  2. In a terminal, in this folder:  npm install

Every time:
  npm run dev        Start the site at http://localhost:5173 (reloads as you edit)
  npm test           Check every question for 150 random students (about 2 s)
  npm run build      Build the finished site into the dist/ folder
  npm run preview    Serve the built site at http://localhost:4173

Opening dist/index.html directly from the file system will not work (browsers
block it); use "npm run preview" or a hosting service.

On GitHub: every push runs the tests and a build automatically (Actions tab,
"CI"). A green tick means all questions passed their checks.

3. WHAT WORKS NOW
-------------------------------------------------------------------------------

Site (dark theme, works on phones):
  Home page               Overview and Phase 1 status.
  Question bank           Browse IB Physics SL by theme and topic; filter by
                          question type or standard; search titles.
  Question preview        Any question with the base numbers or any student's
                          numbers; answer it interactively; switch worked
                          solutions and the IB-style markscheme on or off;
                          "Teacher details" shows the given data, exact answers
                          and the accepted range for every part.
  Assignment builder      Choose a topic, filter by standard, tick questions,
                          save as an assignment. Release or hide solutions per
                          assignment. Print / download a PDF of the base version
                          or of one student's version, with or without worked
                          solutions and markscheme.
  Printable view / PDF    Exam-style paper: name/class/date lines, answer lines
                          with units, writing lines, blank graph grids, then a
                          separate answer-key section. "Download PDF" opens the
                          print dialog; choose "Save as PDF".
  Student view (demo)     Sign in with a class code + username (no password in
                          the demo). Assignment list with progress bars and
                          scores. Work is saved after every change; signing out
                          and back in restores answers, results and the same
                          numbers. Released solutions use the student's numbers.

Question types implemented:
  Calculation       Typed number; checked with the rounding tolerance (section 4).
  Multiple choice   IB Paper 1A style, including "which row is correct" tables.
                    Options are shuffled per student (base version keeps the
                    printed order).
  Graph reading     A randomized graph is part of the question.
  Graph drawing     Students drag points that snap to the grid (mouse, touch
                    or keyboard arrows). Marked point by point.
  Short answer /    Free text, saved as typed, "Submit for marking". Marked by
  long response     the teacher for now (AI marking is deliberately left out).

Marking rules:
  - Online, a correct final answer earns full marks for that part. This is a
    homework policy: the computer cannot see working. On IB papers, "show
    that" questions and some multi-step calculations need working, so the
    printed papers say "show your working" and leave space for it.
  - Error carried forward (ECF), as in IB markschemes: if a student gets (a)
    wrong but uses their wrong value correctly in (b), (b) is marked correct
    and says so. This also works from a drawn graph (the lift question's
    distance is accepted if it matches the area under the student's graph).
  - ECF credit is re-checked whenever an earlier answer changes: correcting
    (a) removes ECF credit that (b) had earned from the old answer.
  - A re-worked answer that is physically impossible (e.g. a negative time or
    distance) never earns ECF credit; positive-only quantities are marked so.
  - Feedback hints: wrong sign, or out by a power of ten (units/prefixes).
  - Unreadable input (including a wrong unit typed after the number) is
    reported as unreadable, not as wrong, and does not use up an attempt.

The 7 IB Physics SL · A.1 Kinematics questions:
  1. Uniformly accelerating train           calculation (suvat), 4 marks
  2. Reaction time and stopping distance    calculation + explain, 6 marks
  3. Velocity–time graph for a cyclist      graph reading + calculation, 5 marks
  4. Drawing a v–t graph for a lift         graph drawing + area, 5 marks
  5. Speed of a falling object              multiple choice, 1 mark
  6. Projectile at the highest point        multiple choice (table), 1 mark
  7. Ball kicked across level ground        long response, 9 marks
All are original questions written in IB style (command terms, "[2]" marks,
IB units such as m s⁻¹, markschemes with ✓ per marking point, ECF/OWTTE
notes). No past-paper questions are copied.

4. ANSWER TOLERANCE: HOW NUMERIC ANSWERS ARE CHECKED
-------------------------------------------------------------------------------

Goal: accept any answer a student could reach by reasonable rounding in each
step, and never penalize significant figures.

There are two stages.

STAGE 1: THE ACCEPTED RANGE (worked out by the computer for each student)

Every question has a compute() function that works out the answers from the
given data, step by step. Any value a student would write down and reuse in a
later step is marked as "carried", for example the vertical velocity in a
projectile question before it is used to find the maximum height.

The system then re-runs the whole calculation many times:
  - each carried value kept at full precision, rounded to 3 s.f., or rounded
    to 2 s.f., in every combination (3 options per carried value). Values
    that are already exact to 3 s.f. or fewer (10.5, 0.48, 84) are carried as
    written, because nobody rounds an exact 10.5 to 11;
  - with every accepted value of each physical constant: for IB, g = 9.8 and
    9.81 m s⁻²; for AP, also g = 10;
  - by every method the worked solution shows. For example, the train's time
    can come from t = (v − u)/a or from distance ÷ average speed, each with
    its own rounding.
  The smallest and largest results form the range. A small extra allowance of
  0.5% of the exact answer is added to each end, to cover calculator and
  rounding quirks that a single path cannot capture. Rounding is done the way
  a person does it (halves round up), not the way binary floating point does.

For a one-step answer, nothing is carried, so the range is just the exact
answer ± 0.5%. For multi-step answers the range widens by exactly as much as
rounding mid-calculation can change the result. Across every allowed set of
numbers in the current questions, the widest range is about −9%: the
projectile's maximum height when v_y ≈ 11.5 is rounded to 11 and then squared.

STAGE 2: COMPARING WHAT THE STUDENT TYPED (no significant-figure penalty)

The student's answer is read with as many significant figures as they typed,
but at least 2. The answer is correct if any value inside the range rounds to
what they typed. In practice:
  - typing more digits is never penalized, provided the value is inside the
    range;
  - a 2 s.f. answer is accepted if it is the correct 2 s.f. rounding of some
    value in the range;
  - a 1 s.f. answer is read as 2 s.f. ("0.5" is treated as "0.50"), so very
    rough answers are not accepted;
  - whole numbers ending in zero ("200") get the benefit of the doubt (they
    could mean 1, 2 or 3 s.f.).

Accepted input formats: 13.8, -0.48, .5, 3.0e8, 3.0x10^8, 3.0*10^8,
3.0×10⁸ and a decimal comma (1,5). A unit may be typed after the number only
if it is the expected one, in any common form ("4 m/s", "4 m s^-1", "4 m s⁻¹");
any other unit ("13.8 km" when metres are expected) is refused with a message,
so a wrong unit is never silently ignored. Malformed entries such as "0.48e",
"0.48x2" or "0.48m+999" are refused, as are the ambiguous "1,500" and
fractions such as 1/3, each with a message explaining why.

ERROR CARRIED FORWARD (ECF)

When a later part is marked wrong, the system checks whether the student got
an earlier part wrong. If so, it re-runs the whole calculation (with all the
rounding options above) using the student's own earlier answer in place of
the correct carried value. If the later answer then falls in range, it is
marked correct, with the message "Correct, using your answer to (a) (error
carried forward)". A question can also define ECF from a non-numeric answer,
such as the area under a graph the student drew. Later parts are re-marked
automatically whenever an earlier answer is edited, and ECF never rescues a
physically impossible value (a negative time, distance or speed).

WORKED SOLUTIONS AND ROUNDING
Worked solutions write intermediate values with one guard digit (4 s.f.)
unless they are exact (0.48, 104.5), and each displayed answer is the one that
working produces, so every displayed step adds up. In rare cases this differs
from the full-precision answer by one in the last digit; both are accepted.
The tests check, for every allowed set of numbers, that each worked
solution's own displayed answer is marked correct.

WORKED EXAMPLES (base versions)

  Train (a): a = (20² − 4.0²)/(2 × 400) = 0.480 m s⁻²
    One step, nothing carried: accepted range 0.4776 to 0.4824.
    0.48, 0.480, 0.478 and 4.8e-1 are accepted. 0.47 and 0.483 are rejected,
    and so is 0.5 (read as 0.50).

  Projectile (b): maximum height h = v_y² / (2g), with v_y = 18 sin 40° = 11.57
    Carried value v_y: 11.5702 (full), 11.6 (3 s.f.), 12 (2 s.f.); g = 9.8 or 9.81.
    Results run from 6.823 (full precision, g = 9.81) to 7.347 (v_y = 12,
    g = 9.8). With the 0.5% allowance, the accepted range is 6.789 to 7.381.
      Accepted: 6.83, 6.830, 6.82, 6.8, 7.3, 7 (read as 7.0), 7.4
      Rejected: 6.78, 6.7, 7.5
    Rounding 11.57 to 12 and then squaring is what widens this range. See
    section 9 for the stricter setting, which gives 6.789 to 6.899 here.

  ECF: a student who answers 0.5 for train (a) and then 32 s for (b), since
  (20 − 4.0)/0.5 = 32, gets (a) wrong and (b) correct by ECF.

OTHER ANSWER TYPES
  Multiple choice   exact choice.
  Graph drawing     marked line segment by line segment, like the markscheme:
                    a segment earns its mark when both of its ends are on the
                    correct vertices (within half a grid square) and nothing
                    else sits between them. Points are matched to vertices in
                    any order, so one misplaced point only costs the segments
                    it touches (e.g. 2/3 for a wrong starting point).
  Written answers   saved and shown as "submitted"; the teacher marks them.

SETTINGS (src/config/site.ts)
  TOLERANCE.carrySigFigs  [3, 2]   rounding levels tried for carried values
  TOLERANCE.minSigFigs    2        answers are read to at least this many s.f.
  TOLERANCE.relFloor      0.005    extra allowance (0.5%) on each end
  CONSTANTS.IB.g          primary 9.8, also accepts 9.81
  A single answer can be widened in its template with tolerance: { rel, abs }.

The markscheme panel shows the range for every numeric part ("Online marking:
accepts any value from 6.79 to 7.38 m, or that value rounded to 2 or more
significant figures"). Because of the second stage, an answer such as 7.4
(a 2 s.f. rounding of 7.38) is accepted even though it is above 7.38.

5. HOW THE PER-STUDENT NUMBERS WORK
-------------------------------------------------------------------------------

Each student's numbers come from a "seed" made of three things:
    student (class code + username)  ::  assignment  ::  question
e.g. "PHYS1:jordan::hw-abc123::ibp-a1-train-acceleration". The seed drives a
deterministic random-number generator (cyrb128 hash + sfc32), so:
  - the same student always gets the same numbers for that assignment, on
    any device, at every login. Nothing needs to be stored to achieve this;
  - different students get different numbers;
  - the same question in two different assignments gets different numbers
    (useful for retakes);
  - worked solutions, markschemes and the printed "student version" PDF use
    exactly the same numbers.
Given data are drawn from ranges with fixed steps (for example 2.0 to 8.0 in
steps of 0.5), so the numbers printed are exactly the numbers used. Templates
can add constraints (e.g. final speed at least 8 m s⁻¹ more than initial
speed). The base version uses each template's default values and is the same
for everyone; it is what printed worksheets use unless you pick a student.

7. HOW TO ADD A QUESTION
-------------------------------------------------------------------------------

  1. Copy a similar file in src/content/ib-physics/a1-kinematics/ and give it
     a new, permanent id (never change an id after students have used it).
  2. Define params (the given data): { min, max, step, base } for each value.
     Add a constraint if some combinations make no sense.
  3. Write compute(p, c): calculate every answer from p. Wrap any value a
     student would write down and reuse in c.carry(value, 'name'), using the
     name of the earlier part's answer to enable ECF. Use c.g for g. If the
     solution shows a second method, return it as "<answer>__<name>" (e.g.
     t__avg) so its rounding is accepted too.
  4. Write the stem and parts: prompt, marks, response type, worked solution
     steps ({ text, math }) and markscheme lines ({ mark } or { note }).
     State the sign convention ("take upwards as positive"). Show values that
     are substituted into later steps with fmtW() and final answers with
     fmtA(); the solution then displays exactly what its working gives.
     Mark times, distances and speeds with positive: true. For ECF from a
     drawn graph or other non-numeric answer, add followThrough.
  5. Add the question to the topic's index.ts, then run: npm test
     The tests will report LaTeX errors, impossible numbers, ranges that are
     too wide, duplicate MCQ options, graph points off the grid, and any
     worked solution whose own answer would be marked wrong.
  6. Look at it in the browser: npm run dev, then Question bank → Preview,
     and try a few students' versions with solutions turned on.

9. DECISIONS TO REVIEW
-------------------------------------------------------------------------------

  - How lenient the rounding allowance is (kept lenient on purpose). Students
    may round carried values to 2 s.f., which is generous when a value is
    squared or has a leading 1 (projectile example in section 4: 7.4 m is
    accepted for an exact 6.83 m; the widest case in the current bank is about
    −9%). For a stricter "keep at least 3 s.f. in working" policy, set
    TOLERANCE.carrySigFigs to [3] in src/config/site.ts; the same example then
    accepts 6.789 to 6.899 m (6.8 and 6.9 accepted, 7.0 and above rejected).
  - Full credit online for a correct final answer is a homework policy (the
    computer cannot see working). Printed papers ask for working and leave
    space for it, for teachers marking by hand with the markscheme.
  - The value of g. Solutions show g = 9.8 m s⁻², the value in the IB Physics
    data booklet (first assessment 2025); 9.81 is accepted too. It is set by
    CONSTANTS.IB.g.primary in src/config/site.ts.
  - Standards numbering. A.1.1–A.1.7 are short labels for the IB guide's
    understandings; the numbering is ours, because the IB lists them as bullets.
  - The organization name is set to "Rice Education" (SITE.orgName in
    src/config/site.ts).
