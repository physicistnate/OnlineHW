1. WHAT THIS IS
-------------------------------------------------------------------------------

A homework system for IB, AP and general high-school physics and
precalculus/calculus. It does not use any existing online homework system.
Phase 1 is a working website with no database yet. Everything a student does
is saved in their own browser, which is enough to test the whole question
engine before real accounts are added in Phase 3.

Courses so far (five): IB Physics SL and IB Physics HL; two trial courses
with one unit each, AP Physics C: Mechanics (Unit 3 Work, Energy, and Power)
and University Physics I, calculus-based (Topic 3 Work, energy and power);
and University Modern Physics, calculus-based, with questions for the ideas
of IB Theme E (Topics 2–7). Course menus group them as IB, AP and
University. HL includes every SL topic and question plus the HL-only topics
(A.4, A.5, B.4, D.4, E.2); a question marked level 'HL' appears only in HL.

Questions so far (103, 625 marks): A.1 Kinematics (12), A.2 Forces and
momentum (15, two of them HL only), A.3 Work, energy and power (13), E.1
Structure of the atom (7, three HL only), E.2 Quantum physics (5, an HL-only
topic), E.3 Radioactive decay (7, three HL only), E.4 Fission (6), E.5 Fusion
and stars (6), AP Unit 3 (10), University Physics I Topic 3 (10) and
University Modern Physics (12). The IB guide has no additional higher level
understandings in A.1, A.2 or A.3; the one HL difference in A.2 is collisions
and explosions in two dimensions, which has its own HL-only standard (A.2.10)
and question. In Theme E the HL understandings are in E.1 (nuclear radius,
closest approach, the Bohr model), E.3 (nuclear stability, the decay
constant) and the whole of E.2; each has HL-only standards and questions.
HL-only standards are hidden in SL courses.

One assignment can mix questions from any courses and topics (section 3,
"Assignment builder").

Technology: a static website (Vite + React + TypeScript), maths rendered with
KaTeX, graphs drawn as SVG. No server is needed, so it can be hosted free on
Cloudflare Pages or Netlify (school wifi blocks GitHub, see section 9). The
planned database is Supabase (free tier).

2. RUNNING IT ON YOUR COMPUTER, AND TESTING CHANGES BEFORE THEY GO LIVE
-------------------------------------------------------------------------------

One-time setup:
  1. Install Node.js 22 (LTS) or newer from https://nodejs.org
  2. In a terminal, in this folder:  npm install

Every time:
  npm run dev        Start the site at http://localhost:5173 (reloads as you edit)
  npm test           Check every question and the grading rules (a few
                     minutes: every question with every allowed set of numbers)
  npm run build      Build the finished site into the dist/ folder
  npm run preview    Serve the built site at http://localhost:4173

Opening dist/index.html directly from the file system will not work (browsers
block it); use "npm run preview" or a hosting service.

On GitHub: every push and pull request runs the tests and a build
automatically (Actions tab, "CI"). A green tick means all checks passed.

How changes reach the live site (main is the base everything builds on):
  1. New work (questions, features, fixes) is done on its own branch, never
     directly on main.
  2. The branch gets a pull request. CI runs the tests on it, and once the
     site is on Cloudflare Pages or Netlify, every pull request also gets its
     own preview address, so new questions can be tried in a browser (and
     reviewed, e.g. by Codex) before anyone else sees them.
  3. When it looks right, merge the pull request. main, and the live site
     built from it, only ever receive tested work.
  Recommended: on GitHub, Settings → Branches → add a rule for main that
  requires a pull request and a passing "CI" check before merging.

To try a pull request on your own computer:
  git fetch origin <branch-name>
  git checkout <branch-name>
  npm install
  npm run dev

3. WHAT WORKS NOW
-------------------------------------------------------------------------------

Site (dark theme, works on phones):
  Home page               Overview and status.
  Question bank           Any course (a menu grouped IB, AP, University), by
                          theme and topic. Choose one or
                          more standards (green ovals, "Select all", "Unselect
                          all"; nothing is shown until at least one is chosen),
                          filter by question type, search titles. Questions
                          that also need ideas from later topics (e.g. kinetic
                          energy, A.3, in an A.2 question) are left out unless
                          "Also include questions that use ideas from later
                          topics" is ticked. "Combine topics" mode instead
                          lists only questions that use every topic chosen
                          (e.g. A.2 + A.3). Choices are kept in the address,
                          so coming back from a preview shows the same list.
  Question preview        Any question with the base numbers or any student's
                          numbers; answer it interactively (unlimited tries);
                          switch worked solutions and the marking key (IB
                          markscheme, AP scoring guidelines or university
                          grading rubric) on or off; "Teacher details" shows the given data,
                          exact answers and the accepted range for every part.
  Assignment builder      1. Choose questions. Pick a course (IB SL or HL, AP,
                             University), then either "One topic" (the default:
                             a topic and one or more standards, with the same
                             later-topics option as the bank) or "Combine
                             topics" (two or more topics; only questions that
                             use all of them, with the instructions shown on
                             the page). Tick questions: they collect in "Your
                             assignment" on the right, in order, and stay there
                             when you change the course or topic, so one
                             assignment can mix IB, AP and university questions
                             from any number of topics. Reorder (↑ ↓), remove
                             one (✕) or "Remove all".
                          2. Settings: tries per part, due date and time,
                             answer key for students (hidden / open now / open
                             after the due date), class-grade rules (penalty
                             per extra try, lowest score per part). Press
                             "Save assignment" once everything is chosen.
                          3. Print / download a PDF of the base version or of
                             one student's version, with or without worked
                             solutions and marking keys, and optionally with
                             the written extension questions (paper only).
                          Saved assignments: "Edit questions" reopens one in
                          the builder (add or remove questions in any course
                          or topic, then "Save changes"; questions it already
                          had keep the version students were given; "Stop
                          editing" leaves it unchanged), edit settings, print
                          the key, open as a student, delete. Each assignment
                          keeps the version of every question it was made
                          with. An unsaved draft (course, mode, topic,
                          standards, topics, chosen questions, settings)
                          survives visits to other pages.
  Printable view / PDF    Exam-style paper: name/class/date lines, answer lines
                          with units, working space, blank graph grids, then a
                          separate answer-key section; shows the due date of a
                          saved assignment. A paper that mixes courses names
                          them all, prints instructions that suit them all
                          and labels each question with its course; its key
                          is headed "Worked solutions and marking keys" and
                          names each question's key in brackets (Markscheme,
                          Scoring guidelines, Grading rubric). Written
                          extension questions ("explain …", "derive …",
                          marked by the teacher) can be added to printed
                          copies, with their marking key.
                          "Download PDF" opens the print dialog; choose "Save
                          as PDF".
  Student view (demo)     Sign in with a class code + username (no password in
                          the demo). Assignment list with due dates, a live
                          countdown, progress, class grade and IB marks. Each
                          assignment: tries left per part, correct parts lock,
                          a countdown, warnings 5 and 1 minutes before the due
                          time, then back to the list; afterwards the
                          assignment is read-only and, if the teacher chose it,
                          shows the answer key with the student's own numbers.
                          Work is saved after every change; a visible warning
                          appears if the browser refuses to save or sign in.

Question types implemented (all marked by the computer):
  Calculation       Typed number; checked with the rounding tolerance (section 4).
  Multiple choice   IB Paper 1A style, including "which row is correct" tables.
                    Options are shuffled per student (base version keeps the
                    printed order).
  Graph reading     A randomized graph is part of the question.
  Sankey diagrams   Drawn to scale on a counting grid (one square = a stated
                    power), with a key; read off and calculated from (A.3).
  HR diagrams       Luminosity against temperature on logarithmic axes, with
                    the main regions shaded and lettered stars on gridlines,
                    so their values can be read exactly (E.5).
  Graph drawing     Students drag points that snap to the grid (mouse, touch
                    or keyboard arrows). Marked segment by segment.
  Written answers   Not online for now: every online part is marked by the
                    computer (the tests enforce this). Written "explain"
                    questions exist as paper-only extensions on some
                    questions (stopping distance, kicked ball, skydiver,
                    trolleys), derivations on three AP questions (variable
                    force, potential function, rough incline) and "show
                    that" derivations on two Modern Physics questions (the
                    parent–daughter equations, the energy of a uniform
                    star): the teacher can print them and mark them by
                    hand; students never see them online. An online part
                    never asks for a derivation it cannot mark: if it
                    mentions one, it says that only the value is marked
                    (the tests check this).

Marking rules (one policy, online and on paper):
  - A correct final answer earns full marks for that part (markschemes say
    "Award [2] for a bald correct answer"). On paper, correct working earns
    marks when the final answer is wrong, so printed papers say "show your
    working" and leave space for it. ("Show that" questions, which need
    working, should not be marked this way; none exist yet.)
  - Error carried forward (ECF), as in IB markschemes: if a student gets (a)
    wrong but uses their wrong value correctly in (b), (b) is marked correct
    and says so. This also works from a drawn graph (the lift question's
    distance is accepted if it matches the area under the student's graph).
    See section 4 for how the earlier answers are combined.
  - ECF uses the earlier parts' CHECKED answers only, never an answer that
    was typed but not checked, so marks always reflect submitted work. When
    an earlier part is checked again, later parts that already have a mark
    are re-marked against it. In an assignment, a part that is already locked
    (correct, or out of tries) keeps its mark.
  - ECF never uses inadmissible inputs (e.g. negative velocity components
    where the question defines them as positive) and never credits a
    physically impossible calculation (e.g. a negative time of flight).
  - Every "Allow ECF from (a)" note in a markscheme is backed by the
    calculation: the tests change each earlier answer a note names and check
    that the later answer follows it. Different methods applied to a
    student's own earlier answer may each be accepted (½kx² or mg(L + x)
    with their x), but no method mixes an earlier answer with one worked out
    from it (a wrong λf with the original Compton shift), so the grader never
    accepts two incompatible answers from the same submission.
  - Feedback hints: wrong sign, or out by a power of ten (units/prefixes).
  - Unreadable input (including a wrong unit typed after the number) is
    reported as unreadable, not as wrong, and does not use up a try.

Theme E standards paraphrase the understandings in the IB guide (first
assessment 2025); the numbering E.1.1, E.1.2, ... is ours. The IB's own site
could not be reached from the environment they were written in, so their
wording and the SL/HL split were checked against published summaries of the
guide, not the guide itself. Please compare them with your copy of the guide
and adjust src/content/catalog.ts if anything differs. The University Modern
Physics outline is ours, modelled on typical calculus-based modern physics
courses.

Constants: IB Theme E questions use the values in the IB data booklet, plus
the Sun's luminosity, radius and mass (src/content/ib-physics/constants.ts).
University Modern Physics questions use 4 s.f. values as US textbooks give
them (src/content/university-modern-physics/constants.ts). Each question
states the values it needs, and the 0.5% allowance covers students who use
more precise ones.

Real-world figures used (check them about once a year and update the
questions' text and constants if they change):
  - Average US home: 865 kW h a month in 2024, about 10 400 kW h a year, at an

4. ANSWER TOLERANCE: HOW NUMERIC ANSWERS ARE CHECKED
-------------------------------------------------------------------------------

Goal: accept any answer a student could reach by reasonable rounding in each
step, and never penalize significant figures.

There are two stages.

STAGE 1: THE ACCEPTED RANGE (worked out by the computer for each student)

Every question has a compute() function that works out the answers from the
given data, step by step. Any value a student would write down and reuse in a
later step is marked as "carried", for example the vertical velocity in a
projectile question before it is used to find the maximum height.

The system then re-runs the whole calculation many times:
  - each carried value kept at full precision, rounded to 3 s.f., or rounded
    to 2 s.f., in every combination (3 options per carried value). Values
    that are already exact to 3 s.f. or fewer (10.5, 0.48, 84) are carried as
    written, because nobody rounds an exact 10.5 to 11;
  - with every accepted value of each physical constant: for IB, g = 9.8 and
    9.81 m s⁻²; for AP, also g = 10;
  - by every method the worked solution shows. For example, the train's time
    can come from t = (v − u)/a or from distance ÷ average speed, each with
    its own rounding. Each method keeps its own range and an answer must fit
    one of them: the gap between two methods is never accepted. (The tests
    check that every method gives the same answer at full precision.)
  For each method, the smallest and largest results form the range. A small
  extra allowance of 0.5% of the exact answer is added to each end, to cover
  calculator and rounding quirks that a single path cannot capture. Rounding
  is done the way a person does it (halves round up), not the way binary
  floating point does.

For a one-step answer, nothing is carried, so the range is just the exact
answer ± 0.5%. For multi-step answers the range widens by exactly as much as
rounding mid-calculation can change the result. Across every allowed set of
numbers in the current questions, the widest range is about −9%: the
projectile's maximum height when v_y ≈ 11.5 is rounded to 11 and then squared.

STAGE 2: COMPARING WHAT THE STUDENT TYPED (no significant-figure penalty)

The student's answer is read with as many significant figures as they typed,
but at least 2. The answer is correct if any value inside the range rounds to
what they typed. In practice:
  - typing more digits is never penalized, provided the value is inside the
    range;
  - a 2 s.f. answer is accepted if it is the correct 2 s.f. rounding of some
    value in the range (so 9.6 rounded to 10 is fine);
  - a 1 s.f. answer is read as 2 s.f. ("0.5" is treated as "0.50"), so very
    rough answers are not accepted;
  - whole numbers ending in zero ("200") get the benefit of the doubt (they
    could mean 1, 2 or 3 s.f.).

Typing extra zeros never makes an answer stricter: 2.0000000000 is read like
2.0 (trailing zeros are not counted as significant figures), so it is accepted
whenever 2.0 would be.

Accepted input formats: 13.8, -0.48, .5, 3.0e8, 3.0E8, 3.0x10^8, 3.0X10^8,
3.0x10^(8), 3.0x10^{8}, 3.0*10^8, 3.0*10**8, 3.0·10^8, 3.0×10⁸ and a decimal
comma (1,5). A unit may be typed after the number only if it is the expected
one, in any common form ("4 m/s", "4 m s^-1", "4 m s⁻¹", "4 m·s⁻¹"); any other
unit ("13.8 km" when metres are expected) is refused with a message, so a
wrong unit is never silently ignored. Answer boxes in AP and university
questions show units with a slash (m/s, N/m); "4 m/s" and "4 m s-1" both
match them. A percentage may be typed with or without the % sign. Malformed entries such as "0.48e",
"0.48x2", "0.48m+999" or "0.48x10^(0}" are refused, as are the ambiguous
"1,500" and fractions such as 1/3, each with a message explaining why.

ZERO ANSWERS AND SCIENTIFIC NOTATION
  - An answer of zero (e.g. the displacement of a ball caught where it was
    thrown) is accepted as 0, 0.0, -0, and any value inside its range (with
    rounded working the range can include small values such as 0.58 m).
    If a zero answer is computed as a difference that cancels, wrap it in
    snapZero(value, ...terms) so it is a clean 0, not 1.1 × 10⁻¹⁵; the tests
    flag answers that look like such left-over rounding noise.
  - Given data can be shown in scientific notation with sci: <s.f.> in the
    parameter (e.g. 3.84 × 10⁸ m); the tests check that every value is shown
    exactly as it is used. Answers are shown in scientific notation outside
    0.01 to 99 999, and the tests check that each answer is accepted when
    typed in every format listed above.

ERROR CARRIED FORWARD (ECF), METHOD BY METHOD
When a later part is marked wrong, the system re-runs the calculation (with
all the rounding options above) using the student's own earlier CHECKED
answers in place of the carried values (an answer typed in an earlier part but
not checked is ignored): wrong answers (error carried forward) and also
accepted rounded ones (0.33 written for 0.325). It tries each earlier answer
on its own first, then in pairs, and so on, because a student may use their
own value from (a) but an unrounded value for (b). Example, stopping distance
(base numbers: s₁ = 14 m, s₂ = 33.3 m, total 47.3 m): a student answers
(a) 10 (wrong), (b) 33 (right, rounded) and (c) 43.3 (= 10 + 33.3): (c) is
marked correct by ECF from (a).
  - The message names only the earlier parts the method actually uses, e.g.
    "Correct, using your answer to (a)(ii) (error carried forward)" or
    "Correct, following on from your rounded answer to (a)". An earlier part
    the method does not use (a wrong horizontal component when finding the
    maximum height) earns nothing and is not mentioned.
  - Earlier answers that break the question's sign conventions (a negative
    component the question defines as positive) are never carried forward.
  - Each question can state its physical assumptions in compute() with
    c.assume(...), e.g. a positive time of flight; a re-worked calculation
    that breaks one earns no credit.
  - A question can also define ECF from a non-numeric answer, such as the
    area under a graph the student drew. A graph left at, or moved back to,
    its starting layout counts as no answer, and "Reset points" clears it.
  - Later parts that already have a mark are re-marked automatically when an
    earlier part is checked again (except parts already locked in an
    assignment). Editing an answer without checking it changes nothing else.
  - Where a value is next subtracted from a similar one (thrust − weight),
    the question can say students keep at least 3 s.f. of it
    (c.carry(value, 'name', 3)); otherwise rounding to 2 s.f. would swing the
    difference far more than any examiner allows.

WORKED SOLUTIONS AND ROUNDING
Worked solutions write intermediate values with one guard digit (4 s.f.)
unless they are exact (0.48, 104.5), and each displayed answer is the one that
working produces, so every displayed step adds up. In rare cases this differs
from the full-precision answer by one in the last digit; both are accepted.
The tests check, for every allowed set of numbers, that each worked
solution's own displayed answer is marked correct, and that displayed sums
and products (14 + 33.33 = 47.3) add up.

WORKED EXAMPLES (base versions)

  Train (a): a = (20² − 4.0²)/(2 × 400) = 0.480 m s⁻²
    One step, nothing carried: accepted range 0.4776 to 0.4824.
    0.48, 0.480, 0.478 and 4.8e-1 are accepted. 0.47 and 0.483 are rejected,
    and so is 0.5 (read as 0.50).

  Projectile (b): maximum height h = v_y² / (2g), with v_y = 18 sin 40° = 11.57
    Carried value v_y: 11.5702 (full), 11.6 (3 s.f.), 12 (2 s.f.); g = 9.8 or 9.81.
    Results run from 6.823 (full precision, g = 9.81) to 7.347 (v_y = 12,
    g = 9.8). With the 0.5% allowance, the accepted range is 6.789 to 7.381.
      Accepted: 6.83, 6.830, 6.82, 6.8, 7.3, 7 (read as 7.0), 7.4
      Rejected: 6.78, 6.7, 7.5
    Rounding 11.57 to 12 and then squaring is what widens this range. See
    section 10 for the stricter setting, which gives 6.789 to 6.899 here.

  ECF: a student who answers 0.5 for train (a) and then 32 s for (b), since
  (20 − 4.0)/0.5 = 32, gets (a) wrong and (b) correct by ECF.

OTHER ANSWER TYPES
  Multiple choice   exact choice.
  Graph drawing     marked line segment by line segment, like the markscheme:
                    a segment earns its mark when both of its ends are on the
                    correct vertices (within half a grid square) and nothing
                    else sits between them. Points are matched to vertices in
                    any order, so one misplaced point only costs the segments
                    it touches (e.g. 2/3 for a wrong starting point).

SETTINGS (src/config/site.ts)
  TOLERANCE.carrySigFigs  [3, 2]   rounding levels tried for carried values
  TOLERANCE.minSigFigs    2        answers are read to at least this many s.f.
  TOLERANCE.relFloor      0.005    extra allowance (0.5%) on each end
  CONSTANTS.IB.g          primary 9.8, also accepts 9.81
  A single answer can be widened in its template with tolerance: { rel, abs }.

The markscheme panel shows the range for every numeric part ("Online marking:
accepts any value from 6.79 to 7.38 m, or that value rounded to 2 or more
significant figures"). Because of the second stage, an answer such as 7.4
(a 2 s.f. rounding of 7.38) is accepted even though it is above 7.38.


-------------------------------------------------------------------------------
5. ASSIGNMENTS: TRIES, DUE DATES, ANSWER KEYS AND GRADES
-------------------------------------------------------------------------------

Each assignment has its own settings (builder step 2, or "Edit settings" on a
saved assignment). Defaults are in ASSIGNMENT_DEFAULTS in src/config/site.ts.

TRIES (per question part)
  - Unlimited, or 1–10 tries per part (default 3). A try is used each time a
    part is checked; unreadable input does not use one.
  - Multiple choice gets half its number of choices, rounded up: 2 tries for
    4 choices, 3 for 5 (half + 1 for an odd number is the same thing), or the
    assignment's limit if that is lower (an assignment with 1 try gives every
    part 1 try).
  - A part locks when it is correct or out of tries. The question preview in
    the bank always allows unlimited tries.

DUE DATE AND TIME
  - Optional. Entered in the teacher's time zone; shown to each student in
    theirs.
  - Students on the assignment page see a countdown. A pop-up warns them 5
    minutes and again 1 minute before the due time ("Your time to submit is
    4:59 (minutes:seconds) away"), with a live countdown. When the time runs
    out they are taken back to their assignment list, with a "Time is up"
    message.
  - After the due time nothing can be checked or changed (answers can still
    be read). Only answers checked before the due time count.
  - Phase 1 runs in the browser, so the deadline uses the device's clock.
    Phase 3 moves checking to the server, which uses the server's clock.

ANSWER KEY FOR STUDENTS
  Hidden, Open now, or Open after the due date. The key is the worked
  solution and markscheme for every part, with that student's own numbers.

GRADES
  Two grades are shown for each question and for the whole assignment:
  - IB marks: the marks the student's latest checked answers would earn on a
    paper (e.g. 12/29). No penalty for extra tries.
  - Class grade (percent): for each part, a correct answer earns 100% minus
    the penalty for each extra try (default 7 percentage points: 100% on the
    1st try, 93% on the 2nd, 86% on the 3rd). A partly correct graph earns its
    fraction minus the same penalty. A part that is still wrong (including
    when it is out of tries) earns the "lowest score" (default 0%), and no
    attempted part drops below it. A part never attempted earns 0%. Parts are
    weighted by their marks.
  Grades are worked out from the saved marks only (questions are not rebuilt),
  which keeps the assignment list fast and is how the Phase 3 gradebook will
  read them.


-------------------------------------------------------------------------------
6. HOW THE PER-STUDENT NUMBERS WORK
-------------------------------------------------------------------------------

Each student's numbers come from a "seed" made of three things:
    student (class code + username)  ::  assignment  ::  question
e.g. "PHYS1:jordan::hw-abc123::ibp-a1-train-acceleration". The seed drives a
deterministic random-number generator (cyrb128 hash + sfc32), so:
  - the same student always gets the same numbers for that assignment, at
    every login;
  - different students get different numbers;
  - the same question in two different assignments gets different numbers
    (useful for retakes);
  - worked solutions, markschemes and the printed "student version" PDF use
    exactly the same numbers.
The numbers are also pinned: the first time a student opens a question, the
numbers they got are saved, so a later change to the question's ranges can
never change numbers a student has already seen. (Phase 1 saves them in the
browser; Phase 3 saves them in the database.)
Each assignment also remembers the version of every question it uses. When a
question that has been assigned is revised, the old version is kept in
src/content/archive/ (section 8), so existing assignments keep the questions,
answers and saved work they were made with.
Given data are drawn from ranges with fixed steps (for example 2.0 to 8.0 in
steps of 0.5), so the numbers printed are exactly the numbers used. Templates
can add constraints (e.g. final speed at least 8 m s⁻¹ more than initial
speed). The base version uses each template's default values and is the same
for everyone; it is what printed worksheets use unless you pick a student.

8. HOW TO ADD (OR REVISE) A QUESTION
-------------------------------------------------------------------------------

Adding a question
  1. Copy a similar file in src/content/ib-physics/<topic folder>/ and give it
     a new, permanent id (never change an id after students have used it).
  2. Tag it: topic, one or more standards from that topic (these drive the
     standards picker now and the per-standard reports and retakes later),
     and level: 'HL' if it is HL-only (required in an HL-only topic or on an
     HL-only standard). If it also needs ideas from another topic, list them
     in uses (standard ids such as 'ibp.A.3.3', or topic ids): that drives
     the later-topics option and Combine topics.
  3. Define params (the given data): { min, max, step, base } for each value,
     with max reached in whole steps from min. Add dp to fix decimal places,
     or sci: <s.f.> for scientific notation. Add a constraint if some
     combinations make no sense.
  4. Write compute(p, c): calculate every answer from p. Wrap any value a
     student would write down and reuse in c.carry(value, 'name'), using the
     name of the earlier part's answer to enable ECF. Use c.g for g. State
     assumptions with c.assume(...). If the solution shows a second method,
     return it as "<answer>__<name>" (e.g. t__avg) so its rounding is
     accepted too; it must give the same answer at full precision. For an
     answer that should be exactly zero, use snapZero().
  5. Write the stem and parts: prompt, marks, response type (numeric, multiple
     choice or graph; no written answers for now), worked solution steps
     ({ text, math }) and markscheme lines ({ mark } or { note }). State the
     sign convention ("take upwards as positive"). Show values that are
     substituted into later steps with fmtW() and final answers with fmtA();
     the solution then displays exactly what its working gives. Mark times,
     distances and speeds with positive: true. For ECF from a drawn graph or
     other non-numeric answer, add followThrough. A written "explain" question
     can be added as a paper-only extension ({ prompt, marks, lines,
     markscheme }); it is printed only when the teacher asks for it.
  6. Add the question to the topic's index.ts, then run: npm test
     The tests report LaTeX errors, impossible numbers, ranges that are too
     wide or do not end on max, given data shown differently from the value
     used, methods that disagree, rounding noise around zero, duplicate MCQ
     options, graph points off the grid, written-answer parts, displayed
     sums, products, squares and simple fractions that do not add up, and any
     worked solution whose own answer would be marked wrong.
  7. Look at it in the browser: npm run dev, then Question bank → Preview,
     and try a few students' versions with solutions turned on.

Revising a question that has already been assigned
  Anything that changes its numbers or answers (ranges, formulas, parts):
  1. Copy the current file into src/content/archive/, change its imports from
     '../../../engine/...' to '../../engine/...', and add it to the list in
     src/content/archive/index.ts.
  2. Edit the original and increase its version.
  Assignments made earlier keep the archived version; new assignments get the
  new one. (Wording-only fixes that change no numbers or answers can be made
  in place without a new version.)

10. DECISIONS TO REVIEW
-------------------------------------------------------------------------------

  - How lenient the rounding allowance is (kept lenient on purpose). Students
    may round carried values to 2 s.f., which is generous when a value is
    squared or has a leading 1 (projectile example in section 4: 7.4 m is
    accepted for an exact 6.83 m; the widest case in the current bank is about
    −9%). For a stricter "keep at least 3 s.f. in working" policy, set
    TOLERANCE.carrySigFigs to [3] in src/config/site.ts; the same example then
    accepts 6.789 to 6.899 m (6.8 and 6.9 accepted, 7.0 and above rejected).
  - Grades: the 7-point penalty per extra try applies to the class grade; the
    IB grade is the marks of the latest answers with no penalty. Tries are
    counted per part (not per question). The lowest score applies to attempted
    parts; a part never attempted counts 0%.
  - Multiple choice tries: half the choices, rounded up, capped by the
    assignment's limit (so "1 try" means 1 try everywhere).
  - In an assignment, a part that is correct or out of tries is locked and
    keeps its mark, even if an earlier answer it followed on from is changed
    later.
  - At the due time, answers that were typed but not checked do not count
    (the warnings tell students to check their answers).
  - The question bank, like the builder, shows no questions until at least
    one standard is chosen.
  - "Later topics" follows the IB guide's order (A.1, A.2, …, E.5), and for
    the AP and university courses their unit or topic order. Questions that
    need a later topic are left out by default; one tick includes them. A
    teacher's own teaching order is on the future-features list.
  - AP questions show g = 9.8 m/s² and also accept 9.81 and 10; university
    questions show 9.8 and accept 9.81. All courses use the same markscheme
    layout and the label "Markscheme" (the AP name is "scoring guidelines").
  - "Combine topics" lists questions that use EVERY chosen topic (not all the
    questions in any of them), so choosing more topics narrows the list.
  - Follow-through uses checked answers only, in the teacher preview as well
    as in assignments, so the same rule applies everywhere.
  - Written "explain" questions are paper-only extensions for now (online
    marking stays computer-only, as decided).
  - Marking policy: a correct final answer earns full marks, online and in
    the printed markschemes ("Award [2] for a bald correct answer"); on paper,
    correct working earns marks when the answer is wrong. For stricter hand
    marking (method marks required), remove those notes from the markschemes
    and change the printed instruction in src/content/catalog.ts.
  - The value of g. Solutions show g = 9.8 m s⁻², the value in the IB Physics
    data booklet (first assessment 2025); 9.81 is accepted too. It is set by
    CONSTANTS.IB.g.primary in src/config/site.ts.
  - Standards numbering. A.1.1–A.1.7 are short labels for the IB guide's
    understandings; the numbering is ours, because the IB lists them as bullets.
  - The organization name is set to "Rice Education" (SITE.orgName in
    src/config/site.ts).
